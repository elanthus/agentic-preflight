- Add `verify SHA --signature`, which asks the forge whether the protected verifier signed the note and reports `verified`, `invalid`, or `absent` in `data.signature`. It runs `gh attestation verify` on the note blob and accepts only a signature from the repository's `.github/workflows/attestation.yml`, run for the protected base branch. `invalid` exits 2 with `signature_invalid`; `absent` exits 0, and it also covers a note that was replaced after it was signed. See [ADR 0004](https://github.com/elanthus/agentic-preflight/blob/main/docs/adr/0004-sign-verified-attestations.md).
- `verify SHA` reports `data.statement`: the note blob's SHA-256 and the predicate that the protected verifier signs.
- Add a `sign` job to the example protected verifier workflow. After `verify` accepts a note, the job signs the note blob's digest with the workflow's OIDC identity and stores the signature in GitHub's attestation store. The signature shows that the base-trusted verifier accepted that exact note. It does not show that a stage ran.
