- The fetches in `start` and in a manual-mode `gate`, and the pushes and remote query in
  `push`, can no longer wait on a prompt while they hold the clone-wide locks. Git's terminal
  credential prompt is off, stdin is empty, and on Linux and macOS the command has no
  controlling terminal, so `ssh` cannot ask about a host key or a key passphrase. A missing
  credential now fails the command. Credential helpers, askpass programs, and SSH agents
  still work.
- A command that waits more than five seconds for a clone-wide lock now says on stderr which
  lock it waits for and which run and process hold it.
