- `stage run --baseline` in `in_place` mode now checks out the base commit under the external validation-worktree root (the user cache by default, or `[worktree] root`) instead of inside `.git`, so test runners that ignore VCS directories, such as Jest, no longer report a false pre-existing failure. In-place runs themselves still execute in the current checkout.
- A baseline scratch worktree that cannot be removed, for example because it was locked, no longer replaces the baseline result with an error. Its `ap/<run-id>-baseline` branch is still deleted, and the run's event log records `baseline_cleanup_failed`.
