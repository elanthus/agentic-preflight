- `stage run --baseline` in `in_place` mode now checks out the base commit under the external validation-worktree root (the user cache by default, or `[worktree] root`) instead of inside `.git`, so test runners that ignore VCS directories, such as Jest, no longer report a false pre-existing failure. In-place runs themselves still execute in the current checkout. In `in_place` mode, a `[worktree] root` inside the repository, which isolated modes already refuse at `start`, now makes `--baseline` a setup failure.
- A baseline scratch worktree that cannot be removed, for example because it was locked, no longer replaces the baseline result with an error. Its `ap/<run-id>-baseline` branch is still deleted, the stage envelope reports `data.baseline_cleanup_failed`, and the run's event log records it. A later `--baseline` check reports the locked path as a setup failure instead of a bare `git worktree add` error, and once the worktree is unlocked it removes the leftover and proceeds.
- A `--baseline` check reclaims what a killed earlier check of the same run left behind: a scratch path that Git still registers as a worktree, even if its directory is gone, and an `ap/<run-id>-baseline` branch that still points at the run's base commit and is not checked out. It never deletes an unregistered directory at the scratch path. A branch that points anywhere else, or is checked out in another worktree, is refused by name and left in place; it is no longer deleted during cleanup.
