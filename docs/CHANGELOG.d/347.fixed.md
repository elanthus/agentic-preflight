- `start` now recovers a run that an interrupted `start` left in `CREATED` or
  `WORKTREE_READY`. The next `start` in that source worktree, with or without `--replace`,
  orphans the interrupted run and creates a fresh one, instead of resuming a run that could
  never advance. It reclaims a clean validation checkout the interrupted run provisioned
  (a reusable runner left on its `ap/` branch, or a strict checkout) and exits 4
  (`needs_human`) naming the checkout when it holds changes or commits. It still refuses
  while the interrupted run's `start` holds its operation lock. The `WORKTREE_READY` hint
  now points to `start` rather than to `status`.
