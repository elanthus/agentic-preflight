What this record proves

A completed run shows

  • The review executor accounted for every included review unit of a diff manifest bound to the reviewed commit. Excluded files stay outside that coverage.
  • Each green lint and test command exited zero against the commit it recorded, and the digest of its redacted output is kept.
  • Every finding was resolved by a recorded decision: a fix commit, a dismissal, or an accepted risk, each with its stated reason.
  • A skipped stage records why it was skipped, not that it succeeded.

It does not show

  • That the review was good, or that the agent understood every unit it marked clean. The same diff reviewed twice can yield different findings.
  • Who acted. The client, the agent's model, the reviewer's model, and the push authorization are self-reported claims, marked as such below.
  • That the record is authentic. Neither this report nor the attestation note is signed; anyone who can update the notes ref can replace a note.
  • That the event log is complete. Its hash chain catches a partial edit. Once the run has an attestation note, the note holds the log's digest at merge-back, so a rewrite of that part is caught too. Later events, such as the gate and the push, and a run without a note are not covered, and a note can itself be replaced.
  • That the run record and the findings come from the same write. They are separate files, and a command that failed between writing the two leaves newer findings beside the older record, with nothing in either file to show it.
  • Anything CI or a human reviewer would check. Treat this as an audit trail, not a replacement for either.
